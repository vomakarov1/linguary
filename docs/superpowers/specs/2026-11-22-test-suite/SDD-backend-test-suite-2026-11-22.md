# SDD-backend: Надёжный прогон тестов

> **Статус:** Accepted

- ADR: [ADR-test-suite-2026-11-22.md](ADR-test-suite-2026-11-22.md)
- PRD: [BRIEF-test-suite-2026-11-22.md](BRIEF-test-suite-2026-11-22.md)
- UX: нет
- Связанные SDD: нет

## 1. Обзор

Меняется запуск набора, одна модульная проверка, порог покрытия строк и три краевые ветки: отказ неподдерживаемого маркера условий, очистка списка записей при подготовке глоссария, отказ восстановления без чтения пустого ключа. Клиент модели, схема базы и веб-интерфейс не меняются, пока закрепляющие проверки зелёные.

Решения ADR, которые здесь обязательны: корень проекта в пути импорта тестового запуска; проверка прокси сама очищает окружение; порог 90% только в команде измерения; ошибка недоступности условий сохраняет смысл.

**Затронутые модули:**

- конфигурация проекта — путь импорта и зависимость измерения покрытия;
- набор тестов — проверка прокси, удаление дубля, новые закрепления;
- совместимость условий — только если закрепление маркера не сходится с кодом;
- подготовка глоссария правки — только если список очищается не так, как словарь;
- хранилище работы — отказ до чтения прогона с пустым ключом.

**Существующий flow:**

- Разработчик запускает полный прогон. Консольный скрипт не видит пакет тестов, сбор прерывается.
- Запуск модулем интерпретатора пакет видит и выполняет набор. На окружении, где прокси уже задан, падают случаи автоматического режима.
- Клиент в автоматическом режиме запоминает адреса из окружения в конструкторе. Проверка подменяет одно имя переменной после того, как другие имена уже заданы.
- Снимок условий с маркером контракта проверяется в совместимости условий и при несоответствии бросает ошибку недоступности условий.
- Подготовка глоссария к правке чистит служебные ключи у словаря. Такая же чистка списка в покрытии строк не отмечена.
- Восстановление читает прогон по идентификатору. Пустой идентификатор даёт предупреждение библиотеки доступа к данным в проверке изоляции отмены. Сама проверка зелёная.

Точки встраивания: секция конфигурации тестового запуска; начало проверки диагностики прокси; вызов чтения прогона в начале восстановления.

### Фаза 1. Запуск набора и изоляция прокси

**ID:** P1
**Цель:** AC-1 и AC-2.
**Зависимости:** нет.

#### [P1.T1] Корень проекта в пути импорта

**Уровень:** Trivial

**Файлы:**

```changeset
~ pyproject.toml
```

**Референсы:** секция `[tool.pytest.ini_options]` в `pyproject.toml`. Сейчас там каталог тестов, строгие метки и автоматический режим асинхронных проверок.

**Что сделать:**

Добавить корень проекта в `pythonpath` этой секции. Импорты вида пакета тестов не переписывать. Руководство не менять: команда полного прогона остаётся прежней.

**Ключевые ограничения:**

- Не добавлять измерение покрытия в параметры каждого прогона.
- Не менять метку медленных тестов.

**Проверка:**

- `uv run pytest --collect-only -q` завершается без ошибки импорта пакета тестов.

#### [P1.T2] Изоляция проверки прокси

**Уровень:** Standard

**Файлы:**

```changeset
~ tests/unit/llm/test_openai_compatible_client.py
```

**Референсы:** `test_proxy_diagnostics_redact_encoded_decoded_credentials` в том же файле. Конструктор клиента запоминает секреты до вызова.

**Что сделать:**

В начале проверки удалить из окружения каждый ключ, в имени которого есть `proxy` без учёта регистра. Для автоматического режима после этого задать только ту переменную, которую проверка уже подменяет. Для своего адреса по-прежнему передавать адрес в настройки. Список ожидаемых секретов не расширять.

**Ключевые ограничения:**

- Не менять клиент и функцию разбора секретов адреса.
- Не печатать значения переменных, которые были в окружении до очистки.
- Подставленный адрес остаётся фиктивным.

> Q-1 — приоритет нескольких адресов этой проверкой не задаётся.

**Проверка:**

- Перед запуском в окружении задан посторонний секрет прокси, которого нет в списке ожиданий проверки. Значение фиктивное, адрес машины не используется и не печатается.
- Запуск только этой проверки без предварительной очистки окружения снаружи: 8 прошедших, постороннего секрета нет в выводе.

#### Проверка фазы

**Автотесты:**

- Сбор всего набора командой `uv run pytest -v`.
- Восемь случаев проверки прокси при заранее заданном постороннем секрете: секрет не попадает в вывод.

**Rollback:**

- Убрать `pythonpath` и вернуть прежнюю подмену одной переменной. Поведение продукта не откатывается, потому что продукт не менялся.

#### [P2.T2] Порог покрытия отдельной командой

**Уровень:** Standard

**Файлы:**

```changeset
~ pyproject.toml
~ uv.lock
~ README.md
```

**Референсы:** раздел Testing в `README.md`. Обычный прогон и прогон без медленных тестов остаются без измерения.

**Что сделать:**

Добавить `pytest-cov` в группу dev и обновить lock. В руководстве рядом с обычным прогоном записать команду измерения покрытия пакета приложения с порогом 90%. В параметры каждого прогона порог не добавлять.

**Ключевые ограничения:**

- Порог — доля строк, источник — пакет приложения, не каталог тестов.
- Порог 90, ниже последнего замера.
- Обычная команда из AC-1 остаётся без покрытия.

**Проверка:**

- `uv run pytest --cov=linguary --cov-fail-under=90 -q` завершается успехом.
- `uv run pytest --collect-only -q` завершается с кодом 0.
- В параметрах каждого прогона нет `--cov`.

---

#### Проверка фазы

**Автотесты:**

- Одна оставшаяся проверка инструкций ремонта.
- Команда с порогом на текущем наборе.

**Непокрытый риск:**

- **Что остаётся непроверенным.** Код, который набор запускает отдельным процессом, в долю строк не входит.
- **Чем компенсируем.** Вход командной строки без аргументов почти не содержит логики; порог это явно не обещает.
- **Регрессия.** Обычный прогон не должен стать медленнее из-за измерения.

**Rollback:**

- Удалить зависимость и абзац руководства. Файл-дубль не восстанавливать, если проверка в пакете llm зелёная.

#### [P3.T1] Закрепить отказ неподдерживаемого маркера

**Уровень:** Standard

**Файлы:**

```changeset
~ tests/integration/processing/test_translation_legacy_compatibility.py
~ src/linguary/application/translation_compatibility.py
```

**Референсы:** `_unavailable` бросает `RecoveryError` с причиной `conditions_unavailable`. Соседние проверки этого файла уже отвергают невоспроизводимый снимок.

**Что сделать:**

Добавить проверку, в которой хранимый снимок равен объекту под проверкой, `prompt_templates` — словарь, профиль — `content-plan-v3`, и единственное отклонение — целочисленный `analysis_contract_version`, не равный 5. Ожидание — `RecoveryError` с причиной `conditions_unavailable`. Не копировать соседний приём, который меняет объект и не записывает снимок обратно: иначе отказ случится раньше проверки маркера. Файл совместимости менять только если это ожидание не выполняется. Смысл ошибки не заменять.

**Ключевые ограничения:**

- Не покрывать в этой задаче успешную ветку маркера 5. Её нет в AC-5.
- Не ослаблять проверку профиля и контрольной суммы шаблонов.

**Проверка:**

- Новая проверка и файл совместимости проходят.
- Если первая версия проверки красная из-за другого типа ошибки, чинится код до прежней ошибки недоступности, затем проверка зелёная.

Запрос правки главы кладёт в контекст словарь, не список: это не менять. Служебные ключи: `id`, `book_id`, `created_at`, `concept_id`. **Ключевые ограничения:**

- Не менять очистку словаря.
- Не выдумывать новые служебные ключи.
- Не менять форму запроса правки главы: в контексте остаётся словарь.

**Проверка:**

- Новая проверка в `tests/unit/application/test_correct_chapter_v2.py` проходит.
- Существующие проверки того же файла остаются зелёными.

#### [P3.T3] Не читать прогон с пустым ключом

**Уровень:** Complex

**Файлы:**

```changeset
~ src/linguary/adapters/db/work_state.py
~ tests/integration/processing/test_processing_run_isolation.py
```

**Референсы:** `begin_recovery_attempt` читает прогон после проверки корня и области. Проверка `test_result_of_a_cancelled_run_is_discarded` уже зелёная и печатает предупреждение о пустом первичном ключе.

**Что сделать:**

После уже существующих проверок корня и области: если `run_id is None`, бросить `RecoveryError('conditions_unavailable', root_id)` и не вызывать `Session.get`. В `test_result_of_a_cancelled_run_is_discarded` постоянно считать `sqlalchemy.exc.SAWarning` ошибкой. Внешний флаг прогона этого не заменяет.

**Ключевые ограничения:**

- Не менять судьбу результата отменённого прогона: он по-прежнему не сохраняется.
- Не подставлять фиктивный идентификатор вместо отказа.
- Ошибка восстановления остаётся прежней по типу и причине.

##### Канонический блок: ALG-01 (ALG) (NORMATIVE)

> NORMATIVE. После проверок корня и области пустой `run_id` не читается.

```text
после уже существующих проверок корня и области:
    если run_id is None:
        raise RecoveryError('conditions_unavailable', root_id)
        не вызывать Session.get
    иначе:
        читать прогон как сейчас
```

**Проверка:**

- `test_result_of_a_cancelled_run_is_discarded` сам считает `sqlalchemy.exc.SAWarning` ошибкой и проходит без внешнего флага предупреждений.
- Полный прогон `uv run pytest -v`: падений нет, один прежний пропуск живой оценки.

## 7. Открытые вопросы

### Q-1. Приоритет нескольких адресов прокси

- **Gates:** нет. Вопрос не блокирует задачи.
- **Контекст:** бриф требует, чтобы проверка прокси не зависела от уже заданного окружения. ADR не меняет клиент. Какой адрес побеждает, если заданы и общий прокси, и прокси для HTTPS, и системный прокси, этой правкой не решается.
- **Текущее решение по умолчанию:** клиент запоминает то, что видит в момент создания. Проверка убирает посторонние переменные и задаёт один адрес.
- **При смене решения:** понадобится отдельное решение о приоритете и новые случаи проверки. P1.T2 при этом остаётся годной как проверка одного адреса.
