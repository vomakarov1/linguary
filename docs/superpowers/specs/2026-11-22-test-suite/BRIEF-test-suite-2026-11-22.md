# BRIEF: Надёжный прогон тестов Linguary

> **Статус:** Accepted

- Дата: 2026-11-22
- Аудитория: разработчик, который запускает автотесты перед сдачей правки
- ADR: [ADR-test-suite-2026-11-22.md](ADR-test-suite-2026-11-22.md)
- SDD: [SDD-backend-test-suite-2026-11-22.md](SDD-backend-test-suite-2026-11-22.md)

## Проблема

Команда из раздела Testing в README не выполняет набор. Сбор обрывается, и зелёный или красный результат продукта не появляется. На машине, где уже заданы переменные прокси, часть проверки сокрытия учётных данных прокси падает, хотя в чистом окружении те же случаи проходят. Предупреждение хранилища о пустом ключе прогона сегодня не роняет тест, но следующий выпуск библиотеки доступа к данным может превратить его в ошибку.

Пока это так, разработчик не может отличить поломку продукта от поломки запуска.

## Для кого

Для человека, который меняет Linguary локально и проверяет набор одной документированной командой. Читатель книги и веб-интерфейс этой правкой не затрагиваются.

## Успех

- Документированная команда полного прогона доходит до выполнения тестов.
- Проверка сокрытия учётных данных прокси проходит и тогда, когда в окружении процесса прокси уже задан.
- В наборе нет второй копии одной и той же проверки инструкций ремонта.
- Доля покрытых строк пакета приложения не опускается ниже согласованного порога.
- Снимок условий с маркером контракта, отличным от поддерживаемого, отвергается.
- Подготовка списка записей глоссария очищает его так же, как записи внутри словаря. Запрос правки главы по-прежнему передаёт словарь.
- Восстановление отменённого прогона не предупреждает о чтении по пустому ключу.
- Полный прогон остаётся зелёным, кроме уже существующего пропуска живой оценки имён.

## Сценарии

1. Разработчик запускает полный прогон командой `uv run pytest -v` из README. Набор собирается и выполняется.
2. Перед проверкой диагностики прокси в окружении есть посторонний секрет прокси, которого нет в списке ожиданий самой проверки. После прогона все восемь случаев проходят, и этого секрета нет в выводе.
3. Разработчик смотрит покрытие после прогона с порогом. Прогон падает, если доля покрытых строк пакета приложения ниже порога.
4. В хранилище попадает снимок условий с неподдерживаемым маркером контракта. Обработка отказывается продолжать, а не принимает снимок.
5. Подготовка глоссария к запросу правки получает список записей. В подготовленном значении нет служебных полей и пустой заметки. Запрос правки главы по-прежнему кладёт в контекст словарь, а не список.
6. Отменённый прогон восстанавливается без идентификатора прогона. Ошибка восстановления прежняя, предупреждения о пустом ключе нет.

## Критерии приёмки

| ID | Критерий | Как проверить |
| --- | --- | --- |
| AC-1 | Полный прогон командой `uv run pytest -v` выполняется, а не останавливается на сборе | Эта команда завершается выполнением тестов |
| AC-2 | Диагностика прокси скрывает и свой фиктивный секрет, и посторонний секрет, заданный до очистки | Все 8 случаев проходят, постороннего секрета нет в выводе, окружение снаружи заранее не чистится |
| AC-3 | Проверка инструкций ремонта одна | В наборе нет второго файла с тем же ожиданием |
| AC-4 | Покрытие строк пакета приложения не ниже 90% | Отдельная команда с порогом 90% завершается успехом на текущем наборе |
| AC-5 | Неподдерживаемый маркер контракта отвергается сам по себе | Снимок совпадает с хранимым, шаблоны — словарь, единственное отклонение — целочисленный маркер не 5. Ожидается ошибка недоступности условий |
| AC-6 | Список записей глоссария очищается так же, как записи внутри словаря | Возврат подготовки глоссария не содержит служебных полей и пустой заметки |
| AC-7 | Пустой идентификатор прогона не читается как сущность | Проверка изоляции отмены сама считает предупреждение о пустом ключе ошибкой и при этом проходит |
| AC-8 | Остальной набор не краснеет | Полный прогон: падений нет, живая оценка имён по-прежнему пропускается без флага |

## Вне объёма

- Поведение страничного скрипта в браузере.
- Порог покрытия ветвей и доведение покрытия до полной доли строк.
- Перенос или удаление живой оценки имён.
- Смена того, откуда клиент модели берёт адрес прокси.
- Публикация книг и правки текста перевода.
- Исправление каждого непокрытого участка крупных модулей анализа и правки.

## Ограничения

- Порог покрытия — 90% строк, ниже последнего замера. Порог не встроен в каждый локальный запуск: измерение замедляет прогон.
- Учётные данные прокси из окружения разработчика не попадают в документы, утверждения тестов и отчёты.
- Ошибка недоступности условий и смысл восстановления прогона не меняются. Меняется только отсутствие чтения по пустому ключу.
